# Инструменты web_fetch и web_search: устройство и перенос

Документ описывает два встроенных инструмента для LLM в Offline Chatter. **web_fetch** скачивает страницу и отдаёт модели её основной текст. **web_search** ищет в интернете через выбранную поисковую систему. Описание не привязано к языку: по нему инструменты можно повторить в другом проекте. Реализация на C# (.NET Framework 4.8, без внешних библиотек, кроме Newtonsoft.Json) приведена как образец.

| Файл | Что внутри |
|---|---|
| `src/OfflineChatter.Core/Tools/WebTools.cs` | Оба инструмента: загрузка, защита локальных адресов, кодировка, кэш, формат ответа |
| `src/OfflineChatter.Core/Tools/WebSearch.cs` | Шаблоны поисковых систем, разбор выдачи (`SerpParser`), раскрытие переадресаций |
| `src/OfflineChatter.Core/Tools/PageExtractor.cs` | Очистка страницы и вывод текста с разметкой Markdown |
| `src/OfflineChatter.Core/Tools/HtmlDom.cs` | Терпимый разбор HTML в дерево (`HtmlParser`, `HtmlNode`) |
| `src/OfflineChatter.Core/Tools/WebToolsSettings.cs` | Настройки, шаблоны User-Agent |
| `src/OfflineChatter.Core/Tools/ToolRegistry.cs` | Регистрация инструментов, офлайн-режим, согласие пользователя |
| `tests/OfflineChatter.Core.Tests/WebToolsTests.cs` | Тесты: очистка, выдача, загрузка через локальный мини-сервер |

---

## 1. Общая схема

```
модель ──вызов──► ToolRegistry ──► WebTools.FetchAsync / SearchAsync
                                     │
                                     ├─ проверка адреса (локальная сеть закрыта)
                                     ├─ загрузка через общий HTTP-сервис (прокси, офлайн-режим, TLS)
                                     ├─ лимит размера, таймаут, кодировка
                                     ├─ HTML → дерево → очистка → текст (PageExtractor)
                                     │   или
                                     ├─ выдача → результаты (SerpParser / JSON SearXNG)
                                     └─ текст ответа для модели (простой текст, не JSON)
```

Принципы:

- **Модели отдаётся простой текст**, не JSON. Маленькие модели (1–9B) читают текст надёжнее, а лишние кавычки и экранирование не тратят токены.
- **Каждое правило очистки отключается.** Эвристики ошибаются на необычной вёрстке, и у пользователя должна быть возможность их выключить.
- **Понятные ошибки вместо пустоты.** Проверка «я не робот», не-текстовый файл, таймаут, 404 возвращаются модели отдельными сообщениями. Ответ «No results» допустим только когда выдача действительно пустая.
- **Все запросы идут через общий HTTP-сервис программы.** Так соблюдаются прокси, офлайн-режим и выбор сетевого интерфейса. Своего HTTP-клиента у инструментов нет.
- **Без внешних библиотек разбора HTML** (требование к весу exe). Для этой задачи хватает небольшого терпимого парсера (раздел 6).

## 2. Описания для модели (OpenAI tools)

Это точный текст, который уходит в `tools` запроса `/chat/completions`:

```json
[
  {
    "type": "function",
    "function": {
      "name": "web_fetch",
      "description": "Download a web page (http/https) and return its main text without menus, ads and footers. A long page is returned in parts: call again with start to read on.",
      "parameters": {
        "type": "object",
        "properties": {
          "url":   { "type": "string",  "description": "Absolute URL of the page" },
          "start": { "type": "integer", "description": "Character offset to continue a truncated page (default 0)" }
        },
        "required": ["url"]
      }
    }
  },
  {
    "type": "function",
    "function": {
      "name": "web_search",
      "description": "Search the web. Returns titles, URLs and short snippets of the results; use web_fetch to read a page from them.",
      "parameters": {
        "type": "object",
        "properties": {
          "query":  { "type": "string", "description": "Search query" },
          "period": { "type": "string", "description": "Optional: only recent results - day, week, month or year" }
        },
        "required": ["query"]
      }
    }
  }
]
```

Описания короткие и на английском: модели всех размеров понимают такие лучше, и они дешевле по токенам (~130–140 токенов на инструмент). Связка «search → fetch» подсказана в описании web_search.

Поведение вокруг вызова:

- **Согласие.** По умолчанию оба инструмента в режиме «спрашивать» (окно подтверждения с аргументами); варианты — «разрешено всегда» и «выключен». Ключи согласия: `builtin:web_fetch`, `builtin:web_search`.
- **Офлайн-режим.** Оба инструмента помечены «нужен интернет» (`NeedsInternet`). В офлайн-режиме они не передаются модели вовсе: вызов всё равно закончился бы ошибкой, а описание занимало бы контекст. В списке настроек они остаются.
- **Своя длина ответа.** Инструменты сами ограничивают длину ответа (`OwnLimit`). Общее обрезание результатов инструментов (20 000 символов) к ним не применяется, иначе пропала бы подсказка о продолжении `start=`.
- **Числа строкой.** Модели часто передают числа строкой (`"start": "1782"`), поэтому `start` читается и из строки, и из числа.

## 3. Настройки

Все значения имеют умолчания и приводятся к допустимым пределам при загрузке. Значение вне пределов заменяется значением по умолчанию.

### Запросы (общие для обоих инструментов)

| Поле | По умолчанию | Пределы | Смысл |
|---|---|---|---|
| `UserAgent` | `ChromeWindows` | перечисление | Шаблон User-Agent (ниже) |
| `CustomUserAgent` | пусто | одна строка | Для шаблона `Custom`. Управляющие символы вырезаются, чтобы вставленный текст не добавил заголовков |
| `AcceptLanguage` | пусто | строка | Заголовок `Accept-Language`, например `ru-RU,ru;q=0.9,en;q=0.5`; пусто — не отправляется |
| `TimeoutSeconds` | 20 | 3–120 | Ожидание всего ответа (заголовки и тело) |
| `MaxDownloadKb` | 2048 | 64–16384 | Сколько скачивать с одной страницы; остаток отбрасывается |
| `AllowLocalAddresses` | false | — | Разрешить модели адреса этого компьютера и локальной сети |

Шаблоны User-Agent. Версии браузеров вынесены в константы: при обновлении меняются в одном месте.

| `Custom` | своя строка; пустая → как `App` |

По умолчанию выбран браузерный шаблон: многие сайты отдают «незнакомым программам» заглушку или 403. Мобильные версии страниц обычно легче и чище.

| Поле | По умолчанию | Что делает |

| `StripComments` | true | Убрать блоки комментариев |

| `Markdown` | true | Заголовки `#`, списки `-` / `1.`, цитаты `>`, код в ```` ``` ```` |
| `MaxChars` | 12000 | Символов текста за один вызов web_fetch (1000–60000) |

### Поиск

| Поле | По умолчанию | Пределы | Смысл |
|---|---|---|---|
| `Engine` | `DuckDuckGo` | перечисление | Поисковая система (раздел 5) |
| `CustomSearchUrl` | пусто | — | Свой адрес выдачи для `Engine = Custom` |
| `SearxngUrl` | пусто | — | Адрес своего SearXNG для `Engine = Searxng` |
| `MaxResults` | 6 | 1–20 | Результатов в ответе |
| `Region` | пусто | `xx-yy` | Регион и язык выдачи: `ru-ru`, `us-en` |
| `SafeSearch` | `Moderate` | Off / Moderate / Strict | Безопасный поиск |
| `Snippets` | true | — | Добавлять к ссылкам фрагменты текста из выдачи |
| `ReadPages` | 0 | 0–3 | Сколько первых результатов сразу скачать и приложить их текст |
| `ReadPageChars` | 3000 | 500–10000 | Символов с каждой такой страницы |
| `ExcludeDomains` | пусто | список | Сайты, которых не должно быть в результатах; домен закрывает и поддомены |

`ExcludeDomains` принимает строку через запятую, пробел или с новой строки. Каждый элемент сводится к имени хоста: схема, путь и `www.` отбрасываются, регистр нижний, повторы убираются. Например, `https://WWW.Example.com/path` → `example.com`.

## 4. web_fetch

### Алгоритм

1. **Разобрать адрес.** У адреса обрезаются пробелы и кавычки `<> " '`. Если схемы нет, но есть точка и нет пробелов, добавляется `https://`: маленькие модели часто пишут `example.com/a`. Разрешены только `http` и `https`, остальное → ошибка «Only absolute http/https URLs are supported».
2. **Проверить локальный адрес**, если `AllowLocalAddresses = false` (правила в разделе 4.2). Проверка идёт **до кэша**, чтобы запрет действовал и на страницу, скачанную раньше, когда адреса ещё были разрешены.
3. **Кэш.** Ключ — адрес плюс набор флагов очистки. Хранятся 4 последние страницы, не дольше 5 минут. Нужен для продолжения длинной страницы: вызов с `start=` не скачивает её заново.
4. **Скачать** (раздел 4.3).
5. **Извлечь текст.** HTML (`text/html`, `application/xhtml+xml` или тип не указан, а тело начинается с `<`) проходит через `PageExtractor`, остальной текст (JSON, plain text, XML) отдаётся как есть.
6. **Сформировать ответ** (раздел 4.4).

### 4.2. Локальные адреса

Защита от SSRF: модель или страница, которую она читает, не должна дотягиваться до роутера, NAS, метаданных облака и служб на этом компьютере.

Проверяется **то, что написано в адресе**, без DNS. Запрос может идти через прокси, который разрешает имена сам, и локальный DNS-ответ всё равно ничего бы не гарантировал. Локальными считаются:

- `localhost`, имя без точки (`http://router/`), окончания `.localhost .local .lan .internal .intranet .home .home.arpa .corp`;
- IPv4: `0.x`, `10.x`, `127.x`, `169.254.x` (в том числе метаданные облака `169.254.169.254`), `172.16–31.x`, `192.168.x`, `100.64–127.x` (CGNAT), `224.x` и выше; десятичная запись `http://2130706433/` разбирается как `127.0.0.1`;
- IPv6: `::1`, `::`, link-local `fe80::/10`, site-local, ULA `fc00::/7`, IPv4-mapped адреса (`::ffff:10.0.0.1`) — по их IPv4-части.

**После переадресаций** проверяется и итоговый адрес: внешний сайт может отправить редирект на `http://192.168.1.1/`. Если итоговый адрес локальный, содержимое модели не отдаётся.

Адреса поисковой системы (раздел 5) этой проверке не подлежат: их задаёт пользователь, и свой SearXNG на `127.0.0.1` должен работать.

### 4.3. Загрузка

- `GET` через общий HTTP-сервис с заголовками `User-Agent` (по шаблону), `Accept: text/html,application/xhtml+xml,application/xml;q=0.9,text/plain;q=0.8,*/*;q=0.5` и `Accept-Language` (если задан). Ответ читается по `ResponseHeadersRead`, то есть потоком.
- **Таймаут** — связанный токен отмены, `CancelAfter(TimeoutSeconds)`. На .NET Framework чтение тела не слушает токен, поэтому по таймауту ответ принудительно закрывается (`token.Register(response.Dispose)`). Если вызов отменил пользователь, это отмена; если сработал таймаут — ошибка «No answer from {host} in {N} s». Различать их нужно, чтобы остановка генерации не превращалась в «ошибку инструмента».
- **Статус** не 2xx → ошибка `HTTP 404 Not Found for host`.
- **Тип содержимого.** Принимается только текст: пустой тип, `text/*`, `application/xhtml+xml`, `application/xml`, `application/json`, `application/javascript`, RSS/Atom, `*+json`, `*+xml`. Остальное (PDF, картинки, архивы) → ошибка `Not a text page: application/pdf`, без скачивания тела.
- **Лимит размера.** Тело читается кусками по 16 КБ до `MaxDownloadKb`; дальше чтение прекращается, и отмечается, что страница обрезана.
- **Кодировка**, по порядку:
  1. `charset` из заголовка `Content-Type`;
  2. BOM: UTF-8, UTF-16 LE/BE;
  3. `charset=` в первых 4 КБ документа (meta) — старые русские сайты отдают `windows-1251` только так;
  4. UTF-8.

  В конце снимается ведущий `U+FEFF`.

### 4.4. Ответ модели

```
Title: How llamas sleep — Farm blog
URL: https://farm.example/blog/sleep

# How llamas sleep
By Ann, 3 May
Llamas sleep lying down, usually at night & in short naps. …

[Truncated: characters 0-11873 of 36037. Call web_fetch with start=11873 to read on.]
```

- `Title:` берётся из `<title>`, а если его нет — из первого `<h1>`. Строка опускается, если заголовка нет совсем.
- `URL:` — итоговый адрес, после переадресаций.
- **Длинная страница отдаётся частями** по `MaxChars`. Конец части сдвигается к ближайшему переводу строки, если он не дальше 400 символов. Последняя строка подсказывает следующий `start`. Модели этот формат понимают и сами запрашивают продолжение.
- Если `start` за концом текста: `No more text: the page has N characters.`
- Если страница длиннее лимита скачивания, последняя часть заканчивается строкой `[The page is larger than the download limit: its end is missing.]`
- Если читаемого текста нет: `The page has no readable text (it may be built by JavaScript).` Так модель понимает, что дело не в её запросе.

## 5. web_search

### 5.1. Поисковые системы и адреса

По умолчанию — **HTML-выдача DuckDuckGo**: работает без ключа, без JavaScript и без своего сервера. Запрос кодируется `Uri.EscapeDataString` (пробел → `%20`).

| Система | Шаблон |
|---|---|
| DuckDuckGo | `https://html.duckduckgo.com/html/?q={query}` |
| Bing | `https://www.bing.com/search?q={query}` |
| Google | `https://www.google.com/search?q={query}&gbv=1` |
| Yandex | `https://yandex.ru/search/?text={query}` |
| Brave | `https://search.brave.com/search?q={query}&source=web` |
| Mojeek | `https://www.mojeek.com/search?q={query}` |
| Startpage | `https://www.startpage.com/do/search?q={query}` |
| Yahoo | `https://search.yahoo.com/search?p={query}` |
| SearXNG | `{SearxngUrl}/search?format=json&q={query}` (JSON API) |
| Свой адрес | `CustomSearchUrl` |

К шаблону дописываются параметры, которые понимает система. Регион `ru-ru` делится на страну (`ru`) и язык (`ru`); одно слово считается и страной, и языком, мусор — «без региона».

| Система | Регион | Безопасный поиск | Период (`period`) |
|---|---|---|---|
| DuckDuckGo | `&kl=ru-ru` | `&kp=1` строгий / `-1` умеренный / `-2` выкл. | `&df=d/w/m/y` |
| Bing | `&mkt=ru-RU` | `&adlt=off/moderate/strict` | — |
| Google | `&hl=ru&gl=ru` | `&safe=active` / `off` | `&tbs=qdr:d/w/m/y` |
| Brave | — | `&safesearch=off/moderate/strict` | `&tf=pd/pw/pm/py` |
| Mojeek | — | `&safe=0/1` | — |
| Startpage | — | — | `&with_date=d/w/m/y` |
| SearXNG | `&language=ru-RU` | `&safesearch=0/1/2` | `&time_range=day/week/month/year` |

`period` от модели нормализуется: `d`, `day`, `today`, `24h` → day; `w`, `week` → week и так далее. Остальные значения дают «без ограничения» и не считаются ошибкой.

**Свой адрес.** Запрос подставляется вместо `{query}`, иначе вместо `%s`, иначе дописывается в конец. Если схемы нет, добавляется `https://`. Регион и прочие параметры в свой адрес **не** дописываются: какие параметры понимает сервер, пользователь знает лучше. Если адрес (свой или SearXNG) не задан, модель получает ошибку с указанием, где его задать.

### 5.2. Разбор выдачи (HTML)

Выдачу разбирает **один общий алгоритм** для всех систем, а не отдельный под каждую вёрстку: вёрстки меняются, а общий признак результата устойчив.

1. Разобрать страницу в дерево (раздел 6), взять `<body>`.
2. Собрать все `<a href>`. Ссылки внутри `nav`, `footer`, `noscript` пропускаются.
3. Определить «сайт» хоста: имя без поддоменов и зоны, с учётом двухуровневых зон (`www.google.co.uk` → `google`, `html.duckduckgo.com` → `duckduckgo`; IP-адрес — целиком). Ссылка на тот же сайт, что и поисковик, — либо обёртка над результатом, либо навигация по выдаче:
   - **раскрыть обёртку** (раздел 5.3); если получился внешний адрес, взять его;
   - иначе пропустить (следующая страница, настройки, реклама через свой домен).
4. Результат — ссылка **в заголовке** (`h1`–`h4` вокруг ссылки или внутри неё). Если таких ссылок меньше трёх (вёрстка без заголовков), берутся все ссылки с текстом от 15 символов.
5. **Один адрес — один результат.** На один результат часто ведут значок, строка с адресом и описание. Ссылки группируются по адресу (без завершающего `/`, без учёта регистра), и в группе выбирается ссылка из заголовка.
6. Заголовок результата — текст `h*` внутри ссылки, иначе текст ссылки.
7. **Описание.** От ссылки поднимаемся к родителю, пока в нём нет другого результата: это «блок результата». Его текст без заголовка, без `cite`, кнопок, полей и ссылок-адресов (текст ссылки без пробелов, но с `.` или `/`) и есть описание. Обрезается до 320 символов. Выделение внутри фразы (`<b>llama</b> is`) склеивается без лишних пробелов, блоки отделяются пробелом.
8. Применить `ExcludeDomains` (точное совпадение хоста или поддомен), взять первые `MaxResults`.

Реклама DuckDuckGo (`duckduckgo.com/y.js?ad_domain=…`) отсекается автоматически: это ссылка на сам поисковик без раскрываемого адреса.

**SearXNG** разбирается из JSON: `results[].title / url / content`. Результаты без `url` пропускаются. Если ответ не JSON → ошибка «SearXNG did not answer with JSON: enable the json format in its settings (search.formats).»

### 5.3. Раскрытие переадресаций

| Обёртка | Где адрес |
|---|---|
| DuckDuckGo `//duckduckgo.com/l/?uddg=…` | параметр `uddg` (URL-кодирован) |
| Google `/url?q=…&sa=U` | параметр `q` |
| Bing `bing.com/ck/a?…&u=a1…` | параметр `u`: после `a1` идёт base64url адреса |
| Yahoo `r.search.yahoo.com/…/RU=…/RK=…` | сегмент пути между `/RU=` и `/RK=` (URL-кодирован) |
| Прочие | параметры `url`, `u`, `target`, `redirect`, если значение начинается с `http(s)://` |

### 5.4. Блокировка и капча

Если результатов нет, первые 60 000 символов страницы проверяются на маркеры проверки (без учёта регистра): `captcha`, `unusual traffic`, `not a robot`, `are you a robot`, `я не робот`, `вы не робот`, `enable javascript`, `anomaly-modal`, `verify you are human`, `automated queries`, `automated requests`, `enablejs`, `/httpservice/retry/`, `anubis`, `verifying your request`, `checking your browser`, `cf-challenge`.

Если маркер найден, модель получает ошибку: «The search engine answered with a robot check or needs JavaScript. The user can pick another search engine or user agent in the Tools settings.» Иначе — «No results».

Живая проверка (ноябрь 2026, нейтральный запрос, User-Agent Chrome Windows):

| Система | Результат |
|---|---|
| DuckDuckGo HTML, Bing, Brave | работают |
| Google | требует JavaScript (страница `/httpservice/retry/enablejs`) |
| Startpage | JS-проверка Anubis |
| Яндекс, Mojeek | проверка «я не робот» |
| Yahoo | из сети разработки не ответил |

В интерфейсе рядом с ненадёжными системами показывается предупреждение.

### 5.5. Ответ модели

```
[1] Llama - Wikipedia
https://en.wikipedia.org/wiki/Llama

[2] Llama | Description & Facts
https://www.britannica.com/animal/llama?a=1&b=2

- `Snippets = false` — строки описаний не выводятся.
- **`ReadPages > 0`.** Первые N результатов скачиваются параллельно, с теми же настройками очистки, но без ссылок. Каждая страница проходит проверку локальных адресов. Если страница не открылась, результат остаётся без текста, без ошибки.
- Пустой итог — `No results`.

## 6. Разбор HTML (`HtmlParser`)

Небольшой терпимый парсер, около 300 строк. Его задача — отделить блоки страницы друг от друга, а не построить точный DOM.

- Узлы: элемент (тег в нижнем регистре, атрибуты, дети) или текст (сущности уже раскрыты `HtmlDecode`).
- Пропускаются комментарии, `<!DOCTYPE>`, `<?xml?>`. Содержимое CDATA берётся как текст.
- `script` и `style` пропускаются целиком, до своего закрывающего тега: строка `'</div>'` внутри скрипта не ломает дерево.
- Содержимое `title` и `textarea` — только текст.
- Пустые элементы: `area base br col embed hr img input link meta param source track wbr` и `<x/>`.
- Неявное закрытие:
  - открытие блочного тега (`div`, `p`, `ul`, `h1`–`h6`, `table`, `section`…) закрывает незакрытый `<p>`;
  - `<li>` закрывает предыдущий `<li>` в пределах `ul`/`ol`; так же `dt`/`dd`, `tr`, `td`/`th`, `option`.
- Закрывающий тег без пары игнорируется; с парой — закрывает всё, что открыто внутри неё.
- Атрибуты: в кавычках, без кавычек, без значения; повторы игнорируются.
- **Глубина ограничена 400 уровнями.** Остальное складывается на этом уровне, чтобы обход дерева не переполнил стек на «дьявольских» страницах (`<div>` × 5000).
- Обходы дерева нерекурсивные (стек или список).

`Measure` считает для каждого узла число непробельных символов текста в поддереве. На этом числе построены эвристики очистки.

## 7. Очистка страницы (`PageExtractor`)

Порядок:

1. Найти `<title>`, взять `<body>`, а если его нет — корень.
2. **Всегда удаляются** `noscript svg template iframe canvas object embed map head link meta title`.
3. `StripBoilerplate`:
   - удалить поля форм и проигрыватели: `select button input textarea video audio dialog datalist`;
   - удалить скрытое: атрибут `hidden`, `aria-hidden="true"`, `display:none` или `visibility:hidden` в `style`;
   - удалить блоки, у которых в `class` или `id` есть слово из списка: `cookie(s) consent gdpr advert(isement) ads ad adsbygoogle promo sponsor(ed) share sharing social subscribe newsletter popup modal overlay related recommended recommendations outbrain taboola banner`.
4. `StripComments` — блоки со словами `comments comment disqus discussion replies`.
5. `StripNavigation`:
   - теги `nav`, `footer`, `aside`;
   - `header` — **только вне** `article`/`main`: `<header>` статьи — это её заголовок, он остаётся;
   - `role`: `navigation banner contentinfo complementary search menu menubar toolbar`;
   - слова в `class`/`id`: `nav navbar navigation menu menubar sidebar footer breadcrumb(s) masthead topbar pagination pager skiplink sitemap`;
   - класс `header` вместе с одним из `site page global top main app sticky fixed`, или `id="header"`.
6. `MainContentOnly` — найти основной блок (раздел 7.2).
7. Вывести текст (раздел 7.3).

### 7.1. Защита от ложных срабатываний

Имена классов ненадёжны: `menu-wrapper` у ресторана — это содержимое, `hero-banner` — заголовок товара. Поэтому блок **не удаляется по имени класса**, если:

- это `html`, `body`, `main` или `article`;
- в нём больше половины текста страницы;
- внутри есть `h1`, `main` или `article`.

Для блоков, опознанных по тегу или роли (`nav`, `footer`, `role=navigation`), проверка доли текста не нужна, но `h1`/`main`/`article` внутри всё равно защищают их от удаления.

**Слова из `class` и `id`.** Значение разбивается по любым небуквенным символам и по границе camelCase: `site-footer mainNav` + `id=cookie_banner` → `site footer main nav cookie banner`. Сравнение идёт по словам целиком, поэтому `adapter` не совпадёт с `ad`.

Удаление идёт сверху вниз: удалённый блок уносит всё вложенное, его потомков проверять не нужно.

### 7.2. Основной блок

1. Пересчитать `Measure` после удалений. «Достаточно текста» — от 200 символов и от четверти текста страницы.
2. Взять самый текстовый `main` или `role=main`, если в нём достаточно текста, иначе `body`.
3. Если внутри **ровно одна** верхнеуровневая `article` с достаточным текстом, взять её. Несколько статей — это лента, тогда остаётся общий блок.
4. **Спускаться по обёрткам**, пока почти весь текст (от 85 %) лежит в одном дочернем `div / section / main / article / span / form / center / table / tbody / tr / td`. Табличные теги включены ради старых сайтов, свёрстанных таблицей.

### 7.3. Вывод текста

- Блочные теги начинают новую строку; `br` — перевод строки; `hr`, `img` — ничего.
- Пробелы схлопываются; неразрывный пробел и `U+200B` считаются пробелами.
- Markdown:
  - `h1`–`h6` → `#`…`######`, перед заголовком пустая строка;
  - `li` → `- `; в `ol` → `1. `, `2. `; вложенность — по два пробела на уровень;
  - `blockquote` → `> `;
  - `pre` → ограждение ```` ``` ````, строки внутри сохраняются как есть, с отступами;
  - таблица → ячейки через ` | `, строка таблицы — строка текста.
- `KeepLinks`: `[текст](абсолютный адрес)`. Относительные адреса раскрываются от итогового URL страницы, `//host` получает схему страницы. Якоря `#…`, `javascript:` и не-http(s) остаются простым текстом.
- `DropDuplicateLines`: повтор строки от 16 символов выбрасывается. Короткие («Да», «5 шт.») повторяются по делу и остаются.
- Несколько пустых строк подряд схлопываются в одну; края обрезаются.

Пример результата для статьи с меню, cookie-баннером, боковой колонкой, кнопками «поделиться», скрытым текстом, комментариями и подвалом (из теста `Keeps_Article_And_Drops_Chrome`):

## 8. Ошибки, которые видит модель

Ошибка возвращается как результат инструмента с флагом `isError`; генерация продолжается, и модель может попробовать иначе.

| Ситуация | Текст |
|---|---|
| Не http(s) или не адрес | `Only absolute http/https URLs are supported` |
| Локальный адрес | `Local and private network addresses are turned off in the Tools settings` |
| Переадресация в локальную сеть | `The address redirects to a local network address` |
| Статус не 2xx | `HTTP 404 Not Found for example.com` |
| Не текст | `Not a text page: application/pdf` |
| Таймаут | `No answer from example.com in 20 s` |
| Капча или JS у поисковика | `The search engine answered with a robot check or needs JavaScript. The user can pick another search engine or user agent in the Tools settings.` |
| Не задан SearXNG или свой адрес | `The SearXNG address is not set (Tools settings).` / `The custom search address is not set (Tools settings).` |
| Офлайн-режим | инструменты не предлагаются модели; прямой вызов отклоняет HTTP-сервис |

Тексты ошибок на английском, как и описания инструментов: их читает модель, а не пользователь. Отмена пользователем пробрасывается как отмена, а не как ошибка инструмента.

## 9. Перенос в другой проект

### Что нужно от окружения

- HTTP-клиент с потоковым чтением тела, переадресациями, gzip/deflate и общим прокси.
- JSON для аргументов и ответа SearXNG.
- Таблица кодировок с `windows-1251` и `koi8-r`. В .NET Core / .NET 5+ это `CodePagesEncodingProvider`; в .NET Framework встроено.
- Ничего больше: разбор HTML и выдачи — свой код, без зависимостей.

### Порядок

1. Перенести `HtmlDom.cs` и `PageExtractor.cs`. Они не зависят ни от чего, кроме BCL; есть тесты на разбор и очистку.
2. Перенести `WebSearch.cs`: шаблоны, разбор выдачи, раскрытие переадресаций.
3. Перенести `WebToolsSettings.cs`. Значения по умолчанию и пределы — из таблиц раздела 3.
4. Переписать загрузку из `WebTools.cs` под свой HTTP-клиент. Сохранить порядок проверок: адрес → кэш → загрузка → проверка итогового адреса → статус → тип → лимит → кодировка.
5. Зарегистрировать инструменты с описаниями из раздела 2. Учесть согласие пользователя и офлайн-режим.
6. Перенести тесты. Загрузку удобно тестировать мини-сервером на `TcpListener` по `127.0.0.1` с `AllowLocalAddresses = true`. Второй адрес петли `127.0.0.2` пригодится, чтобы отличать сервер поиска от сервера страниц.

### Что проверить после переноса

- [ ] Очистка: тест со статьёй (меню, cookie, sidebar, share, скрытое, комментарии, подвал); каждое правило по отдельности; `PageCleanOptions.Raw` сохраняет весь текст.
- [ ] Ресторанное меню (`menu-wrapper` с основным текстом) и `hero-banner` с `h1` не удаляются.
- [ ] Битая разметка (`<p>` без закрытия, `<li>` вне списка, `a < b`), 5000 вложенных `div`, пустая строка.
- [ ] Выдача DuckDuckGo без рекламы; обёртки Bing (base64), Google (`/url?q=`), Yahoo (`/RU=`); вёрстка без заголовков.
- [ ] Капча и JS-страницы дают ошибку, а не «No results».
- [ ] Адреса: таблица локальных (IPv4, IPv6, десятичная запись, mapped, имена без точки, `.local`) и внешних.
- [ ] web_fetch: заголовки User-Agent и Accept-Language уходят; windows-1251 из meta; PDF отклоняется; 404; лимит скачивания; таймаут через 1 с; отмена — это отмена.
- [ ] Продолжение `start=` не скачивает страницу второй раз.
- [ ] Офлайн-режим убирает оба инструмента из запроса к модели.
- [ ] Живая проверка: DuckDuckGo, Bing, Brave дают результаты; Википедия и README на GitHub очищаются до статьи.

## 10. Ограничения

- **JavaScript не выполняется.** Одностраничные приложения отдают пустой текст, и модель получает об этом сообщение. Помог бы безголовый браузер, но он противоречит весу и требованиям к Win7.
- **Эвристики очистки** настроены на распространённую вёрстку: на необычных сайтах они могут убрать нужное или оставить лишнее. Поэтому каждое правило выключается в настройках.
- **Шаблоны поисковых систем** зависят от их политики к автоматическим запросам и со временем ломаются. Устойчивее всего HTML-выдача DuckDuckGo и свой SearXNG.
- **Версии браузеров** в шаблонах User-Agent нужно иногда обновлять: слишком старая версия сама по себе повод для проверки «я не робот».
- **PDF и документы** не читаются (тип содержимого отклоняется до скачивания тела).
- **Робот-правила** (`robots.txt`) не проверяются: инструмент работает по запросу пользователя, как браузер, а не как поисковый робот.
