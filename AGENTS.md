# AGENTS.md — правила для ИИ-агентов и контрибьюторов

Прочитай этот файл целиком перед любыми изменениями. Цели продукта описаны в [README.md](README.md), план и текущий статус в [TODO.md](TODO.md).

## Жёсткие ограничения

1. **Целевая платформа: .NET Framework 4.8** (`net48`), WPF, C# `LangVersion=latest`. Не переводить проект на .NET Core / .NET 5+: они не работают на Win7.
2. **Windows 7 SP1 — первый класс поддержки.** Всё, что появилось после Win7, нужно:
   - вызывать только после проверки версии ОС (`OsInfo`) или через `GetProcAddress`;
   - обеспечить запасной вариант на случай, если функция недоступна.
   Это касается WinRT, `SetThreadDescription`, `DwmSetWindowAttribute` с новыми атрибутами, DXGI 1.4 и т. п.
3. **Вес.** Цель для exe со всеми зависимостями — 4–6 МБ. Новую NuGet-зависимость можно добавлять только если:
   - она поддерживает net48 / netstandard2.0;
   - она не тянет Microsoft.Extensions.\* и System.Text.Json;
   - в PR указан её вклад в размер.
   Разрешённый список см. ниже.
4. **Нельзя:** WebView2 / CefSharp / Electron-подобные компоненты, `AllowsTransparency=true` на главных окнах (это медленно), блокирующий I/O в UI-потоке.
5. **Git.** Агент не делает коммиты и push: репозиторием управляет владелец вручную.

Поставка: в релизе только архивы (zip, rar) и два установщика (обычный и `-Setup-NET48` со встроенным офлайн-установщиком .NET Framework 4.8), без голого exe. .NET в zip не кладётся: zip скачивает обновление внутри программы. `installer/OfflineChatter.iss` хранится в UTF-8 с BOM (иначе Inno Setup испортит русские строки). Источник релизов зашит в `UpdateChecker.Repo` (`fhnb16/offline-chatter`) и в настройках не меняется; список релизов и SHA-256 для обновления программы берутся только из официального `api.github.com` (зеркало API из настроек не используется), принимаются только файлы из `github.com/fhnb16/offline-chatter/releases/download/`. Win7-сборки llama.cpp берутся из `fhnb16/win7.llama.cpp`; по умолчанию этот канал выбирается на Windows 7. Обновление внутри программы скачивает zip — менять формат или имена (`OfflineChatter-X.Y.N.zip`, папка `OfflineChatter\` внутри) можно только вместе с `UpdateChecker.IsPackage` / `ExtractPackage` и их тестами.

Подпись Authenticode: exe подписывается в CI до упаковки, установщик и деинсталлятор — через `SignTool` Inno Setup; всё — только через `tools/sign.ps1` (сертификат из секретов, README → «Подпись»). Обновление принимается по правилам `UpdateSignaturePolicy` (Core, с тестами): действительная подпись — ставить, нет подписи или она недоверенная — спросить пользователя, повреждённая — всегда отказ. Проверка подписи — `Shell/Authenticode` (`WinVerifyTrust` без проверки отзыва); `ElevatedUpdate` перед заменой файла сверяет SHA-256 с одобренным файлом и повторяет проверку. Не пропускать проверку при ошибке.

- **Core не зависит от WPF.** Всё, что можно протестировать без UI, кладётся в Core.
- Весь P/Invoke находится в `Interop/`, в классах `NativeMethods` по DLL. Для каждой функции указана минимальная версия ОС.
- MVVM: View ↔ ViewModel только через биндинги и команды. Code-behind допустим для чисто визуальной логики (WindowChrome, анимации).

## Темы и оформление

- `ThemeManager` — единая точка управления. Он отвечает за:
  - **скин** (системный словарь `PresentationFramework.{Aero|Aero2|AeroLite|Luna|Royale|Classic}` или Fluent);
  - **подложку** окна (None / AeroGlass / Win10Blur / Win10Acrylic / Mica / MicaAlt / Acrylic);
  - **акцент** (системный или свой);
  - **светлую / тёмную** тему.
- Стили, которые выглядят по-разному в скинах (`SearchBox`, `TabStrip`, `TabStripItem`), задаёт сам скин: Fluent.xaml — свои шаблоны, системные скины — `ThemeManager.AddNativeKeyedStyles` на основе родных стилей. В разметке ссылаться на них только через `DynamicResource`, иначе при смене скина останется старый вид. Свои шаблоны в Shared.xaml допустимы только для того, что одинаково во всех скинах.
- Цвета в XAML берутся только через `DynamicResource` с ключами из `ThemeKeys` (`Theming/ThemeTokens.cs`, там же значения для светлой/тёмной темы и каждой подложки). Литералы цветов в разметке запрещены.
- Каждая подложка обязана деградировать плавно: если ОС или режим не поддерживают эффект, используется сплошной фон. На Win7 также учитывается выключенная композиция DWM (Aero Basic / Classic) и событие `WM_DWMCOMPOSITIONCHANGED`.
- Окна с собственным заголовком на Win11 обязаны поддерживать Snap Layouts (`HTMAXBUTTON` в `WM_NCHITTEST`).
- Каждое окно подключается через `ThemeManager.Attach(window)` в конструкторе. Подложка применяется в `SourceInitialized` и **повторно в `ContentRendered`**: Win11 25H2 при первом показе сам выставляет тёмный заголовок по системной теме.
- `SetWindowCompositionAttribute` (Blur, Acrylic через SWCA) используется только на Win10, включая его «выключение». На Win11 с расширенной рамкой он даёт чёрный фон, там работает `DWMWA_SYSTEMBACKDROP_TYPE`. На Win10 рамка DWM для SWCA расширяется только на полосу заголовка (под системные кнопки; `ShellChrome` captionGlassOnly) или на 1 px: расширенную область DWM заливает сплошным цветом рамки, и при `-1` всё окно получается тёмным пятном вместо размытия.
- Атрибуты DWM окна (тёмный заголовок, тип подложки) может переписать не только программа. Сторонние утилиты вроде **Mica For Everyone** ставят всем окнам свои заголовок и подложку на события окна: показ, смену шаблона (при каждой смене скина WPF), запрос заголовка `WM_GETTEXT`. Поэтому:
  - после применения темы и при активации окна `ThemeManager` сверяет фактические атрибуты (`WindowBackdrop.Verify`) и переприменяет их;
  - после `WM_GETTEXT` с наивысшим приоритетом диспетчера ставится быстрая правка без сброса подложки (`WindowBackdrop.QuickFix`);
  - `SetPreferredAppMode` (uxtheme #135) сообщает Windows тему приложения.
  Полностью моргание убирает только исключение в самой утилите: «Настройки → Оформление» распознают Mica For Everyone и добавляют правило (`ExternalThemeTools`). Не убирать эту защиту: без неё светлая тема на тёмной подложке нечитаема.
- Настройки оформления меняются только точечно (одно поле) и только через `ThemeManager.Apply`; `AppearanceViewModel` перечитывает значения после каждого `ThemeManager.Changed`. Иначе страница настроек перезапишет изменения из палитры команд или командной строки.
- Проверка тем на лету: `pwsh tools/theme-tour.ps1 -Exe <exe> -Out <папка>` — одно окно, смена оформления ключом `--appearance Skin:Mode:Backdrop`, снимок и фактические атрибуты DWM после каждого шага.
## Вёрстка и тон интерфейса

Основа — скилл **unslop** (Damir Sokolovsky, CC BY 4.0): [docs/design/unslop/SKILL.md](docs/design/unslop/SKILL.md). Он написан для веба (React/Tailwind); ниже — как его правила переносятся на WPF этого проекта. Справочников `references/*` из исходного пакета в репозитории нет — при спорных случаях смотреть сам SKILL.md.

Направление:
- **Продукт** — рабочий инструмент для локальных моделей; человек приходит спросить, сравнить, настроить и уйти. **Характер** — спокойный, точный, без рекламности. **Мир** — родное окно Windows своей версии (Aero на 7, плоско на 8, Fluent/Mica на 10/11), а не веб-страница. **Моменты** — первый ответ модели, установка в один клик, честная статистика. **Подпись** — моноширинные цифры статистики под ответом и тихие строки состояния (офлайн, обновление) в боковой панели.

Правила:
- Акцентный цвет — только для главного действия экрана (отправить, скачать, установить) и выделения. «Новый чат», «Использовать», «Запустить» — обычные кнопки. Пузырь пользователя — нейтральная поверхность с лёгким оттенком акцента.
- Никаких эмодзи в интерфейсе: иконки — векторные `Geometry` из `Skins/Shared.xaml` (на Win7 нет иконочных шрифтов).
- Текст — с заглавной только первое слово, без восклицательных знаков; подсказки объясняют последствия, а не повторяют название.
- Цифры (tok/s, мс, токены, порты, ключи) — стилем `StatText` или `MonoFontFamily`.
- Сетка 4 px: отступы 4/8/12/16/24.
- **Резиновая вёрстка.** Не использовать `MaxWidth` + `HorizontalAlignment="Left"` у страниц и фиксированные `Width` у полей ввода. Строка «подпись — контрол» — `Controls/AdaptiveRow` (на узком окне контрол уходит под подпись), карточки рядом — `Controls/ResponsiveGrid`, ряды кнопок — `WrapPanel`. Проверять при ширине окна 760 px и на весь экран.
- Действия под сообщением — в общем потоке вёрстки, никаких отрицательных отступов, которые обрезает контейнер.

### Чеклист перед сдачей изменений UI

- [ ] Направление (выше) соблюдено; экран не подошёл бы любому другому продукту, если заменить название
- [ ] Отступы кратны 4; одинаковые элементы (строки списка, карточки в ряду) одного размера и с одним отступом
- [ ] Иконки, подписи и числа стоят ровными колонками; ширина места под иконку одинакова во всех строках
- [ ] Цвета только через `DynamicResource` из `ThemeKeys`; три роли текста (`TextPrimary/Secondary/Tertiary`); акцент — один и редко
- [ ] Нет градиентов между оттенками, свечения, цветных теней; рамки — тонкие нейтральные (`CardBorder`, `Divider`)
- [ ] Нет эмодзи в интерфейсе; иконки — из `Skins/Shared.xaml`, 16 px, одна толщина линии (`IconPath`), цвет — по роли текста
- [ ] Шрифт — системный (`AppFontFamily`) + моноширинный для цифр; насыщенность не выше SemiBold; нет КАПСА с разрядкой и курсива
- [ ] Строки в `Strings.tsv`: без восклицательных знаков; короткие (одно предложение) — без точки в конце; без «волшебных» слов и непроверяемых обещаний
- [ ] Числа в одном формате, моноширинные (`StatText`)
- [ ] Скругления вложенных элементов согласованы (внутренний = внешний − отступ, не меньше 4); не всё делать «таблетками»
- [ ] Нет зацикленной анимации у того, что не «живое»; индикатор прогресса — только пока идёт работа
- [ ] Окно проверено при ширине 760 px и на весь экран: ничего не обрезается, нет пустой полосы справа
- [ ] Проверено в светлой и тёмной теме и хотя бы в двух скинах (Fluent и Aero/Aero2); текст читается на каждой подложке

## Хранилище и безопасность

- Пути берутся только из `AppPaths`, `Environment.CurrentDirectory` не используется. Портативный режим включается, если в папку с exe можно писать или рядом лежит `portable.flag`.
- JSON записывается атомарно: сначала `*.tmp`, затем `File.Replace` / `Move`.
- Секреты (API-ключи, токен HF) хранятся только через `Secrets` (DPAPI или мастер-пароль). В логах и диагностике они маскируются.
- Содержимое сообщений по умолчанию не логируется.
- `llama-server` слушает только `127.0.0.1` и запускается со случайным портом и `--api-key`. Постоянный порт, свой ключ и доступ из LAN — только если пользователь включил «Локальный API» (настройки).
- Все внешние запросы — только через `HttpService`: он соблюдает офлайн-режим (`OfflineModeException`), прокси (HTTP/SOCKS5/SOCKS5h) и выбранный сетевой интерфейс. Свой `HttpClient` для внешних адресов не создавать (исключение — `LocalHttp` к своему llama-server).
- Для каждого внешнего MCP-инструмента пользователь подтверждает вызов, если явно не разрешил его заранее.

## Стиль кода

- Nullable reference types включены (`<Nullable>enable</Nullable>`). Предупреждения не игнорировать.
- Async до самого верха. Везде, где есть I/O, передаётся `CancellationToken`. `.Result` / `.Wait()` в UI-потоке запрещены.
- В библиотеке Core используется `ConfigureAwait(false)`.
- Имена на английском. Комментарии на русском или английском, но только там, где без них непонятно, *почему* код написан именно так.
- Строки UI: добавить строку в `src/OfflineChatter/Localization/Strings.tsv` (ключ, EN, RU через табуляцию) и запустить `pwsh tools/gen-strings.ps1` — он пересоздаст `Strings.resx` и `StringsRu.resx` (вручную их не править). В XAML — `{l:Loc Key}`, в коде — `L.Get("Key")` / `L.F("Key", args)`. Строковые литералы в XAML не допускаются.
- Названия значений enum в UI: ключ `Enum_{Тип}_{Значение}` + конвертер `EnumDisplay`.

## Ручная проверка UI

```powershell
pwsh tools/screenshot.ps1 -Exe src/OfflineChatter/bin/Debug/net48/OfflineChatter.exe -Out shot.png `
     -Skin Aero -Mode Light -Backdrop Auto -Language en -Page Settings -HitTestMaxButton
```
Скрипт правит `config/settings.json` рядом с exe (`-Width`/`-Height` — размер окна), запускает приложение (`-Page` открывает раздел, `-Section` — вкладку настроек), снимает окно и закрывает его. Окно выводится на передний план и снимается с экрана — не запускайте скрипт, пока за компьютером работает человек.

## Сборка и проверка

```powershell
dotnet build OfflineChatter.sln -c Debug
dotnet test  OfflineChatter.sln
```

Перед тем как считать задачу выполненной:
1. Сборка проходит без новых предупреждений.
2. Тесты Core зелёные. Новая логика в Core покрыта тестами.
3. При изменениях UI или тем сценарий проверен вручную хотя бы на текущей ОС, а в описании отмечено, что нужно проверить на Win7 / 8.1 / 10 / 11.
4. Если задача из [TODO.md](TODO.md), её чекбокс отмечен.
